# 讲解重点提纲（teaching_outline）

- **版本**：v0.5
- **用途**：在结构要点之后，产出**讲解重点提纲**（非全文示范课），帮助带教与新老师调整讲法与课程设计
- **上游 / 契约**：薄标准讲课呈现；A08（术语先通俗后专名）；报告契约 §1.15～1.16 / §9 / §10；共屏授课默认；须回避 Pass A `issue`；lab 遵守 L1/L2/L3

## 输入

用户消息提供：

1. `title_anchor`、`lesson_type`（`principle` \| `code` \| `lab`）
2. `structure.md`（含主交付与是否硬套总分总）
3. 纠错逐字稿（可已剥元前言）
4. Pass A 中须回避的 `issue` 列表（claim + quote + remediation）

## 输出结构（Markdown）

## 硬约束

1. **偏提纲**：禁止输出接近全文的示范课；每段示范口吻最多 2 句。
2. **必须回避**用户消息中列出的 Pass A `issue`：提纲不得重复错误定义/错误类比；应用 remediation 方向改写。
3. 标题锚点定范围；禁止用百科「应讲清单」扩写成另一套讲义。
4. **主交付优先**：提纲须显式写出本段主交付 1～2 点；「本课讲解重点」不得把五个以上并列小点写成同等必讲且无递进。若 `structure.md` 判定硬套总分总，提纲应示范**合并后的主线**，而不是复述散点清单。
5. 课型字段必须与用户给出的 `lesson_type` 一致（不要擅自改课型）。本仓三值为上游六课型的 MVP 子集（见报告契约 §7.1）。
6. **lab**：提纲须按建议路径组织；若本课把注意事项前置或安装中插官网，分段提纲仍按**建议路径**写，并在「实操主线」对比实际顺序。默认验证只一条；扩展后置。
7. **非 lab**：禁止输出「实操主线」节，也禁止写「不适用」。
8. 关键术语：示范口吻宜「先通俗或已知概念，再给出规范术语」，对齐 A08；不要一上来堆未解释的专名。
9. 对事不对人；完整句子；遵守共屏媒介，禁止默认「板书」。
10. **直接输出 Markdown 正文**；禁止用 ```markdown 代码块包裹整篇；禁止解释性前言。
