# ADR-0005：讲清度（clarity）、待回放边界与表达噪声闸门

- **Status**：Accepted
- **Date**：2026-07-25
- **Relates to**：ADR-0004（不替代两段式与假阳性闸门；在其上补充类别与 Pass B 边界）

## Context

维护者用同主题（NLP 注意力 / QKV）三节课对照现有 Pass A/B 后发现：

1. **假阴性**：课已用类比「讲到」QKV，但**关系与应用机制未讲清**时，Pass A 往往只给 `coverage_gap`（待核实）或空 findings，summary 仍写「讲解清晰」。
2. **coach 越权 / 错位**：仅凭逐字稿难以判断共屏画面（PPT / 笔记 / IDE）、后半课、真实互动；同时易把口头禅等**不损害教学效果**的表达噪声抬进 Top3。
3. ADR-0004 的「宁可漏报、不可错杀」仍然成立，但需区分：
   - **整块未出现**（可能在下一节）→ 继续待核实；
   - **本段已声称讲清 / 实现，机制却未落地**→ 应可在有摘句时进入必改候选。

## Options considered

| 选项                                           | 优点                     | 缺点                               |
| ---------------------------------------------- | ------------------------ | ---------------------------------- |
| 维持仅 accuracy/case/coverage_gap              | 改动小                   | 持续漏检「讲了但没讲清」           |
| 用百科必讲清单抬高召回                         | 易检出机制缺失           | 假阳性上升，违背 ADR-0004          |
| 新增 `clarity` + summary 约束 + 待回放节       | 对准假阴性；保留摘句闸门 | 提示词与渲染需同步；需主题自检克制 |
| 为 coach 引入视频多模态 / 共屏画面 OCR（同期） | 减少「待回放」           | 超出当前 MVP；媒体与成本膨胀       |

## Decision

1. **Pass A 增加 `category=clarity`**：标题锚点承诺的核心关系 / 机制是否在稿中**可操作地讲清**；`issue` 仍须非空摘句与高置信。
2. **`clarity` ≠ `coverage_gap`**：整块未出现 → `coverage_gap` + `unverified`；本段口头承诺已覆盖但机制未落地 → `clarity`（可 `issue`）。
3. **`summary` 禁无依据褒奖**：空 findings 或仅有 coverage_gap / 全 unverified 时，禁止「清晰 / 恰当 / 到位」类总评。
4. **Top3 权重**：准确性 > 讲清度 ≥ 案例 > 结构/递进 > 表达/沟通；本段讲清度优先于「课表后半截未上」类结构项。
5. **表达噪声闸门**：口头禅、边打字边讲等，无「损害理解」摘句证明时，不得进 Top3 / 合格线。
6. **`coach.md` / `report.md` 增加「待回放确认」**：显式列出转写无法判定项；不强行定论。建议用语对齐**共屏授课**（桌面共享），不默认黑板板书。
7. **本阶段仍不做**：讲义库、百科必讲清单打分、强制多模态 / 共屏 OCR。

字段、验收表与报告模板以 [报告契约 v0.3.1](../../01-product/003_report-contract_报告结构与验收.md) 为准。

## Consequences

### 正面

- 对准「讲了但没讲清」假阴性，同时保留摘句闸门；
- coach 承认逐字稿边界，减少硬判画面与互动；
- 表达类建议更贴「是否损害教学效果」，符合教练而非监工。

### 负面

- Pass A / Pass B 提示词与 JSON 渲染需一次对齐改动；
- `clarity` 边界仍依赖模型克制，弱标题时须更保守（继承 ADR-0004）；
- 「待回放」增多时，维护者仍需抽查视频（可接受）。
