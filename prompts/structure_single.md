# 单视频结构提炼（structure_single）

- **版本**：v0.4
- **用途**：从纠错逐字稿提炼总分总、小闭环与递进（单视频）
- **上游引用**：
  - `teaching-quality-enablement` → `docs/02-标准与工具/002_教学能力模型_授课力维度体系_双场景.md`（V2 设计力为主）
  - 本仓报告契约：`docs/01-product/003_report-contract_报告结构与验收.md` §10（lab）

## 假设（MVP）

单节视频按**总分总**组织；段内宜有小闭环且整体有递进。若转写无法支持，写「转写未体现」，不要编造。

用户消息含 `lesson_type`（`principle` \| `code` \| `lab`）。**仅当 `lesson_type=lab` 时**输出「实操套路自检」整节；非 lab **不要**输出该节标题，也不要写「不适用」。

## 输出结构（Markdown）

```markdown
## 课程结构与要点

### 总—分—总自检

- 开场总：
- 分述要点：
  - …
- 结尾总：
- 明显缺口：

### 小闭环与递进

- 各段小闭环是否清楚：
- 递进关系：
- 缺口：

### 实操套路自检（仅 lesson_type=lab 时输出本节）

- 本课实际顺序（据转写）：
- L1 对照推荐路径「作用 → 实操 → 验证 → 总结注意事项 → 扩展」：
- L2 主线 vs 扩展（最短主线是否先闭环；备选源/工具是否后置）：
- L3 默认验证路径（一条；并列第二种是否标扩展；分步确认不算多验证）：
- 建议讲解路径（写清；若本课注意事项前置或安装中插官网，须给出改法路径）：
- 主线验证路径（择一）：
- 宜标为扩展的内容：
```

## 约束

1. 事实与判断分开；缺口写清缺在哪一功能。
2. **不要**在本步判定知识对错或案例好坏（由 Pass A 负责）。
3. 遵守 `system_tone`：对事不对人。
4. **lab**：禁止用原理课「why→what→how→verify」夸奖递进；不要把「并列两种验证」或「主线未完就展开备选扩展」写成优点。若本课是「作用→注意事项→实操→验证」，须标明偏离 L1，并写建议路径「作用→实操→验证→总结注意事项→扩展」。
5. **直接输出 Markdown 正文**；禁止用 ```markdown 代码块包裹整篇；禁止解释性前言。
