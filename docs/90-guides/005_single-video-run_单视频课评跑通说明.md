# 单视频课评跑通说明（KR4.1 / M1b 闸门）

- **版本**：v0.3
- **日期**：2026-08-07
- **用途**：按步骤复现「抽轨 → 转写 → 纠错 → Pass A → 结构 → 提纲 → 教练报告」单视频端到端；落实 **纠错稿人工闸门**；读报告时遵守 **主交付优先**
- **产品源**：[PRD](../01-product/001_prd_课评教练MVP产品说明.md)、[CLI 契约](../01-product/002_cli-contract_CLI命令与运行契约.md)、[报告契约](../01-product/003_report-contract_报告结构与验收.md)
- **竖切**：`03-delivery` **E4c / M1b**（单视频教练可用 → 分校带教优先内测）
- **前置**：已完成 [开发环境与 uv](../03-delivery/003_dev-environment_开发环境与uv.md)；本地 `.env` 含 `LLM_API_KEY`；手头有一份**脱敏**样例媒体（不入库）

---

## 1. 学习目标

读完并按本文操作后，应当能够：

1. 在本机对单个视频跑通 `lesson-review run`；
2. 指出 `output/<run_id>/` 下关键产物与阅读顺序；
3. 用退出码区分输入错误、依赖缺失与流水线失败；
4. 在把 `coach.md` / `report.md` 交给分校带教试读之前，完成**纠错稿闸门**与必要的修正记录。

---

## 2. 一次完整运行

将路径替换为本地脱敏样例（示例仅示意）：

```bash
cd /path/to/lesson-review-ai
uv sync
uv run lesson-review check
uv run lesson-review run "data/input/<脱敏样例>.mp4" --lesson-type principle
```

可选：

| 选项            | 说明                                               |
| --------------- | -------------------------------------------------- |
| `--lesson-type` | `principle` \| `code` \| `lab`；非法值会报错退出   |
| `--dry-run`     | 只校验依赖与输入，不调用模型                       |
| `--skip-llm`    | 只做到转写，写出 `transcript_raw.json` 与 manifest |
| `--output-dir`  | 默认 `./output`                                    |

实操安装类样例建议显式传 `--lesson-type lab`，或依赖文件名启发式（见报告契约 §10.1）。

---

## 3. 预期产物与阅读顺序

成功后终端会打印 `run_id` 与报告路径。目录大致为：

```text
output/<run_id>/
  manifest.json
  transcript_raw.json
  transcript_corrected.md
  knowledge_review.json
  structure.md
  teaching_outline.md
  coach.md
  suggestions.md
  report.md
```

建议阅读顺序（**机器产出后、外发前**）：

1. **`transcript_corrected.md`**：通读纠错稿（闸门，见 §4）。
2. **`report.md`**：完整课评（含专业预审渲染、结构、建议）。
3. **`coach.md`**：可发给老师 / 带教试读的短稿（结论 / Top3 / V1–V4）。
4. **`suggestions.md`**：合格线 / 水平线 / 待回放（仅进报告）。
5. **`manifest.json`**：模型、课型来源、可复现元数据。

## 4. 纠错稿闸门（M1b 硬规矩）

现用成本优先模型易出现：完成度夸大、主交付定性偏移、结构「过于顺滑」。两案投诉核查已证明：**未通读纠错稿，不得把报告当带教外发或校区对齐依据**。

### 4.1 何时必须过闸

| 场景                    | 要求                                                                |
| ----------------------- | ------------------------------------------------------------------- |
| 维护者自用试读          | 建议过闸；发现问题写入修正记录                                      |
| **分校带教试读 / 内测** | **必须**过闸                                                        |
| 据此写校区私下对齐备忘  | **必须**过闸（批处理见 [004](./004_batch-conduct_言行扫描速查.md)） |
| 仅调试 CLI / dry-run    | 可不写修正记录                                                      |

### 4.2 闸门步骤

1. **通读**本段 `transcript_corrected.md`（不要只扫标题或只看 `report` 摘要）。
2. **对照** `structure.md` / `teaching_outline.md` / `coach.md`（或批处理 `summary.md`）：
   - 主线是否说成了实际没讲清的内容；
   - 是否把「打算做 / 下去写」写成「已完成 / 已验证」；
   - 本段**主交付**是否被次要话题淹没；
   - 是否硬套总分总外壳而交付点罗列无递进。
3. **有偏差则先改产物**（或注明待回放），再考虑外发。
4. **写入修正记录**（本地 `output/`，**不入库**）：供后续改 prompts 与模型选型对照。

### 4.3 修正记录模板（本地文件）

建议路径：`output/<run_id或课例目录>/summary_修正记录.md`（单视频可改名为 `report_修正记录.md`）。

```markdown
# 修正记录 · 模型跑偏对照

- 目录 / run_id：
- 对照材料：`transcript_corrected.md`
- 日期：
- 原模型：（成本优先 / 其他）

## 跑偏摘要

| 位置 | 原表述问题 | 修正或处置 | 类型（完成度夸大 / 主交付偏移 / 其他） |
| ---- | ---------- | ---------- | -------------------------------------- |
|      |            |            |                                        |

## 选型或提示词启示（可选）

-
```

### 4.4 赋能顺序（提醒）

```text
维护者过闸并验收单视频教练
  → 分校带教优先内测（先提升自身课程设计与教学能力）
  → 带教用同一口径带新老师
  → 暂不开放全体老师自查
```

## 5. 主交付读法与投诉选锚（E4c-2）

报告与结构遵守契约 **主交付优先 / 反硬套总分总**（§1.15～1.16）：

1. 先看 `structure.md` 的「主交付（本段 1～2 点）」与「是否硬套总分总」。
2. `coach.md` / 合格线应优先盯主交付是否讲清；次要话题缺闭环不应刷满必改项。
3. 若判定硬套总分总，改法应是合并点、重排递进或写明唯一带走什么，而不是「结构不好」。

**投诉 / 日课深挖建议顺序：**

1. `batch-conduct`（可选 `--with-outline`）看时长、细课型与言行；
2. 通读相关段纠错稿并过闸（§4）；
3. **点选 1～2 段**（主诉最相关），用文件名或标题作具体锚点；
4. 对该段跑 `lesson-review run … --lesson-type …`；
5. 再读 `coach.md` / `report.md`；需要时写校区备忘。

标题过泛时（如仅有 day05），预期更多「待核实 / 待回放」；不要指望一次 `run` 覆盖整天所有话题。

## 6. 退出码（摘要）

| 码  | 含义                                     |
| --- | ---------------------------------------- |
| 0   | 成功                                     |
| 1   | 用户输入错误（文件不存在、格式不支持等） |
| 2   | 依赖缺失（ffmpeg、模型、无 API Key 等）  |
| 3   | 流水线步骤失败（转写或 LLM 调用失败等）  |

完整约定见 CLI 契约 §4。

---

## 7. 常见失败与处理

| 现象                         | 处理方向                                           |
| ---------------------------- | -------------------------------------------------- |
| `check` 报缺 ffmpeg          | `brew install ffmpeg`；确认 PATH                   |
| `LLM_API_KEY` missing        | 按 `.env.example` 配置本地 `.env`（勿提交）        |
| 首次转写很慢                 | mlx-whisper 下载模型；等待缓存完成                 |
| `--lesson-type lib` 报错     | 仅允许 principle / code / lab                      |
| 报告建议空泛或课型不对       | 指定 `--lesson-type`；对照 prompts 与报告契约回归  |
| 报告「看起来完整」但与稿不符 | **先过 §4 闸门**；写入修正记录后再改 prompts       |
| 合格线被次要嵌套刷屏         | 对照 §5 主交付优先；检查 structure / coach prompts |

分步调试可用：`extract-audio` → `transcribe` → `correct`（见 CLI 契约与 [003 开发闭环](./003_cli-dev-loop_本仓开发闭环.md)）。
