# 讲解重点提纲（teaching_outline）

- **版本**：v0.1
- **用途**：在结构要点之后，产出**讲解重点提纲**（非全文示范课），帮助新老师调整讲法
- **上游 / 契约**：报告契约 v0.5 §2 / §9；公屏授课默认；须回避 Pass A `issue`

## 输入

用户消息提供：

1. `title_anchor`、`lesson_type`（`principle` \| `code` \| `lab`）
2. `structure.md`
3. 纠错逐字稿（可已剥元前言）
4. Pass A 中须回避的 `issue` 列表（claim + quote + remediation）

## 输出结构（Markdown）

```markdown
# 讲解重点提纲

- **课型**：principle | code | lab
- **说明**：参考提纲，非标准讲义；公屏（PPT / 笔记 / IDE）演示，禁止默认板书。

## 本课讲解重点

（3～7 条要点，按总分总顺序；每条一句话）

## 分段提纲

### 段 1 ·（对应结构中的段落名）

- 讲解重点：
- 示范口吻（可选，最多 2 句短话）：

（按结构分段续写；不要写成整节课逐字稿）

## 须回避的讲法（来自专业预审）

（逐条复述须回避点；若输入列表为空，写「本段 Pass A 无高置信 issue」。）

## 公屏演示提示（按课型）

- principle：建议在 PPT / 笔记中标出关系图或关键词
- code：建议切换到 IDE 指出关键 API / 调用顺序（不写完整可运行工程）
- lab：建议按步骤列出学员跟做检查点（不代替实验手册）
```

## 硬约束

1. **偏提纲**：禁止输出接近全文的示范课；每段示范口吻最多 2 句。
2. **必须回避**用户消息中列出的 Pass A `issue`：提纲不得重复错误定义/错误类比；应用 remediation 方向改写。
3. 标题锚点定范围；禁止用百科「应讲清单」扩写成另一套讲义。
4. 课型字段必须与用户给出的 `lesson_type` 一致（不要擅自改课型）。
5. 对事不对人；完整句子；遵守公屏媒介，禁止默认「板书」。
6. **直接输出 Markdown 正文**；禁止用 ```markdown 代码块包裹整篇；禁止解释性前言。
