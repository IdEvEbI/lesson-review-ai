# 讲解重点提纲（teaching_outline）

- **版本**：v0.3
- **用途**：在结构要点之后，产出**讲解重点提纲**（非全文示范课），帮助新老师调整讲法
- **上游 / 契约**：报告契约 §9 / §10；共屏授课默认；须回避 Pass A `issue`；lab 遵守 L1/L2/L3

## 输入

用户消息提供：

1. `title_anchor`、`lesson_type`（`principle` \| `code` \| `lab`）
2. `structure.md`
3. 纠错逐字稿（可已剥元前言）
4. Pass A 中须回避的 `issue` 列表（claim + quote + remediation）

## 输出结构（Markdown）

非 lab 时**不要**输出「## 实操主线」整节（不要写「不适用」）。

```markdown
# 讲解重点提纲

- **课型**：principle | code | lab
- **说明**：参考提纲，非标准讲义；共屏（PPT / 笔记 / IDE）演示，禁止默认板书。

## 本课讲解重点

（3～7 条要点；lab 时按**建议路径**排序，不要照抄本课错误顺序）

## 分段提纲

### 段 1 ·（对应建议路径中的段落名）

- 讲解重点：
- 示范口吻（可选，最多 2 句短话）：

（按建议路径分段；不要写成整节课逐字稿）

## 须回避的讲法（来自专业预审）

（逐条复述须回避点；若输入列表为空，写「本段 Pass A 无高置信 issue」。）

## 共屏演示提示（按课型）

（只写与当前课型相关的一条；不要罗列三种课型。）

## 实操主线（仅 lesson_type=lab 时输出本节；必须写满，禁止「不适用」）

- **建议讲解路径**：作用 → 实操 → 验证 → 总结注意事项 → 扩展
- **本课实际顺序（据转写）**：
- **主线步骤（最短跟做）**：
- **跟做检查点**：

- **总结注意事项**（放在验证之后）：
- **扩展**（官网下载、备选工具、第二种验证等，主线闭环后再讲）：
```

## 硬约束

1. **偏提纲**：禁止输出接近全文的示范课；每段示范口吻最多 2 句。
2. **必须回避**用户消息中列出的 Pass A `issue`：提纲不得重复错误定义/错误类比；应用 remediation 方向改写。
3. 标题锚点定范围；禁止用百科「应讲清单」扩写成另一套讲义。
4. 课型字段必须与用户给出的 `lesson_type` 一致（不要擅自改课型）。
5. **lab**：提纲须按建议路径组织；若本课把注意事项前置或安装中插官网，分段提纲仍按**建议路径**写，并在「实操主线」对比实际顺序。默认验证只一条；扩展后置。
6. **非 lab**：禁止输出「实操主线」节，也禁止写「不适用」。
7. 对事不对人；完整句子；遵守共屏媒介，禁止默认「板书」。
8. **直接输出 Markdown 正文**；禁止用 ```markdown 代码块包裹整篇；禁止解释性前言。
