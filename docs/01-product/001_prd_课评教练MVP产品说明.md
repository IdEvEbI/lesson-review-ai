## 1. 问题陈述

听课与带教复盘依赖个人经验，难复制；样片多时，难以对每一段视频给出稳定、可执行的反馈。课评教练把「听懂讲了什么 → 对照总分总与教学标准 → 给出改法」做成可重复流水线，先服务维护者本人迭代口径，再逐步交给导师带新人。

## 2. 维护者与目标

| 项   | 说明                                                                                                                        |
| ---- | --------------------------------------------------------------------------------------------------------------------------- |
| 用户 | 本仓维护者，职责为教学质量相关赋能与工具先行                                                                                |
| 角色 | 质量架构师 / 发现者 / AI 先行者                                                                                             |
| 场景 | 线下现场培训与线上培训（具体品牌不在本仓公开文档中展开）                                                                    |
| 媒介 | **共屏（桌面共享）**：教师 PPT、笔记软件、IDE 等推送到每位学员屏幕；**不使用黑板板书**                                      |
| 课型 | 本仓 CLI 使用三值子集 `principle` / `code` / `lab`；对应上游备课方法**六课型**的映射见报告契约 §7.1；实操套路见报告契约 §10 |
| 推动 | 教学质量相关事实向上对齐决策层；校区改进通过校区负责人推动                                                                  |

详细定位、飞轮、授权与「三不三要」见上游：`docs/00-定位与方法/001_role-charter_质量架构师角色宪章.md`。

**工程目标**：做出可演示、可迭代的课评教练流水线，把课堂视频变成结构清晰、建议可执行的报告。

**业务目标（对齐宪章成功画像）**：

- 半年视角：校区感到来的人是给方法的，工具是教练不是监工。
- 一年视角：具备可用的 AI 辅助质量监控 / 带教复盘能力。
- 本 MVP：先让维护者自己用得起来；再交给分校导师带新人复盘；成熟后才考虑老师自查。

### 2.1 目标用户与场景（MVP）

| 用户         | 场景                         | MVP 是否覆盖   |
| ------------ | ---------------------------- | -------------- |
| 维护者本人   | 单节课复盘、巡课后自测提示词 | 是             |
| 分校导师     | 带新人看视频复盘             | 否（内测阶段） |
| 全体老师自查 | 自愿上传自查                 | 否             |

**MVP 第一用户只有维护者本人**；报告默认私密，不进入公开考核或羞辱性场合。

### 2.2 处事风格（报告与产品文案必须遵守）

1. **以建立可复用系统为导向**：输出可执行改法，避免只堆批评。
2. **三不三要**：不公开批评校区负责人/教师；不越级指挥一线；不只带问题走；要私下对齐；通过校区负责人推动；带方法走。
3. **对事不对人**：报告默认私密；分享给新人时由导师控制场合。
4. **合格线与水平线**：必须改的与锦上添花的要分开写；不要把发展项写成进班否决语气。
5. **先保证可读，再追求简短**：使用完整句子；禁止电报体；中英文之间保留空格。
6. **公开仓脱敏**：不写维护者真名、所在机构或对外品牌名。

## 3. 产品能力（In Scope）

### 3.1 输入模式

| 模式       | 输入                         | 排序规则                       |
| ---------- | ---------------------------- | ------------------------------ |
| 单视频     | 1 个视频或音频文件           | 不适用                         |
| 模块批处理 | 手动选定的 3～5 个同模块视频 | 文件名前缀数字升序（如 `01_`） |

- 不自动判断「是否同一模块」。若文件名前缀数字缺号或重号，CLI 应发出警告，并仍按可解析的数字升序处理。
- 假设：单视频内部为总分总结构；模块内各视频之间为总分总嵌套。

### 3.2 评价尺子（对齐上游 005 §4.3）

| 来源（上游）             | 本仓用法                                                                          |
| ------------------------ | --------------------------------------------------------------------------------- |
| **授课与做课薄标准**     | prompts / 结构与呈现检查的**首选**口径；合格线与水平线必须分开写                  |
| 备课方法（六课型专文等） | 细则缺口或课型专属硬项时回链；不另立第二套「好课」总标准                          |
| 授课力维度（双场景）     | Pass A 主要对齐 V1；报告本步只展开 V1–V4                                          |
| 课研 001 / 002           | 定档 / 打分参照；**不是**日常课评结构检查或 Pass A/B 门禁                         |
| A07 授课禁忌与底线       | `batch-conduct` 等旁路话术筛查的判定全文；薄标准 §5 仅为分类索引                  |
| A08 讲解可理解性等       | 表达类建议可对齐「衔接 / 术语先通俗后专名」；自信度、时长预估等不纳入本版报告门禁 |

**做课 vs 讲课证据边界**：薄标准区分课前「做课」齐备与课中「讲课」呈现。单视频转写通常**无法核验**讲义 / PPT / 练习是否齐备；凡属做课齐备性或共屏画面类判断，写入「待回放确认 / 材料不可见」，**不得**仅凭稿子写成合格线必改。

### 3.3 流水线（用户可见步骤）

1. **抽轨**（仅视频）：得到用于转写的音频。
2. **转写**：生成带时间信息的原始逐字稿。
3. **纠错**：在保留术语的前提下减少口误与 ASR 噪声；避免「改顺了却改错专业含义」。
4. **结构与要点**：单视频一层；模块模式输出**模块层 + 各视频层**；检查口径首选薄标准「讲课」项。
5. **提升建议与改法**：区分合格线与水平线；对事不对人；避免空泛套话。

### 3.4 输出

- 默认：**一份 Markdown 课评报告**（路径见 [003 报告契约](./003_report-contract_报告结构与验收.md)）。
- 可选中间产物（本地 `output/`，不入库）：原始转写、纠错稿、运行清单（manifest）。

### 3.5 交互形态（MVP）

- **CLI**：维护者在终端指定输入与模式，等待流水线完成，在 `output/` 阅读报告。
- **不做**：Web 门户、账号体系、多人协作、自动归模块。

### 3.6 旁路能力（非课评主路径）

- **`batch-conduct`**：对目录内多个视频按文件名前缀数字排序，依次执行抽轨、转写、纠错，再进行**高风险话术 / 言行扫描**（须摘句；判定对齐上游 A07，薄标准 §5 作类别索引）。
- 用途：投诉核查、课堂用语证据汇总；服务上游当月计划中「批量高风险话术筛查」类关键结果。该旁路**不**执行 Pass A 预审，也不生成教练报告。
- 输出：`output/<输入目录名>/summary.md`（与 `data/input/<同名>/` 对应），以及各段 `transcript_corrected.md`、`conduct_scan.json`。操作见 [004 言行扫描](../90-guides/004_batch-conduct_言行扫描速查.md)；契约见 [CLI 契约](./002_cli-contract_CLI命令与运行契约.md)。
- **旁路增强（E4b-3 / Issue #33）**，仍属投诉 / 日分布核查，**不**替代主路径课评：
  1. `summary` 写入各段**视频总时长**与批合计（看授课节奏）；
  2. 按纠错稿推断上游备课 **004～010** 细课型（判不出为 `other`，维护者可校准），并给出**时长加权**日分布；
  3. 可选：`--with-outline` 各段**讲解结构提纲**（节点少、宜带时间锚），用于观察「点散 / 缺主线」。
  4. 已有批产出可用 `batch-enrich` 补时长与细课型（不重跑 Whisper）；改 `pedagogy_type.json` 后用 `batch-refresh-summary` 重渲。
- **不在本旁路做**：把声学「有底气」打成合格线分数；主路径三值 `principle|code|lab` 门禁枚举不因本旁路扩成七课型。

## 4. 成功标准（可验收）

满足以下全部条件时，视为 MVP 竖切过关：

1. 在维护者提供的**脱敏样例**上，单视频模式端到端跑通并产出报告。
2. 在至少一组 **3～5 个**模块视频上跑通，报告含模块层与各视频层结构。
3. 报告能指出总分总或嵌套上的**具体缺口**，而不是只给出笼统评价。
4. 建议能落到「哪一段 / 缺什么 / 怎么改」，并对照薄标准区分合格线与水平线；不得用课研打分表替代薄标准判定。
5. 维护者愿意把该工具纳入个人复盘习惯（主观标准，但对产品是否可用至关重要）。

## 5. 明确不做（Out of Scope）

- 不做全员自查产品化，也不做复杂权限与绩效默认挂钩。
- 不自动判断视频是否属于同一模块。
- 不用 AI 语音加 PPT 一键生成正式授课成片。
- 不做讲义 / 教案 / 大纲的一键完美生成（属于愿景阶段 ②）。
- 不在本仓另立「组织级教学质量总标准」。
- 未经授权，不把真实课评报告写入公开月报或公开批评场合。
- 不把本工具默认做成全员绩效考核入口。

## 6. 非功能需求（MVP 级）

| 维度   | 要求                                                                          |
| ------ | ----------------------------------------------------------------------------- |
| 隐私   | 真实课例媒体与 API 密钥不进 Git；转写默认本地 ASR                             |
| 可复现 | 每次运行记录模型、提示词版本、输入指纹（见架构 manifest）                     |

| 性能   | 在 M 系列 Mac（24GB）上，单节 45～90 分钟课例可在合理时间内完成（不作硬 SLA） |

## 8. 测试与验证策略（MVP）

- 种子阶段**不要求**将自动化 CI 设为合并门禁；里程碑 PR 合并前，由维护者试用并判断报告质量。
- **回归课例**：固定保留 1 个单视频与 1 组模块视频；改动 `prompts/` 后，对比报告差异。
- **人工检查清单**：检查语气是否符合三不三要、是否区分合格线与水平线、术语是否被误改、模块模式结构是否双层。
