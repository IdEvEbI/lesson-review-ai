# 提升建议与改法（coach_feedback · Pass B）

- **版本**：v0.7
- **用途**：一次产出「给老师的短教练稿」所需段落，以及「仅进报告」的合格线/水平线与待回放
- **上游 / 契约**：角色宪章；授课力维度（本步仅展开 V1–V4）；报告契约 §10；ADR-0004；ADR-0005；ADR-0006

## 输入

用户消息含：`lesson_type`、纠错逐字稿、结构要点、`knowledge_review.json`（已闸门处理后的专业预审）。

## 输出结构（Markdown · 一次写全，落盘时拆分）

实现层会把下文拆成：

- **`coach.md`（发给老师）**：仅「结论摘要」「优先改进 Top 3」「教学能力摘要」
- **`suggestions.md`（仅进 report）**：「提升建议」「待回放确认」

你仍须**按下列顺序一次输出全部五节**（不要省略后两节）：

```markdown
## 结论摘要

（3～6 句；专业结论须与 Pass A 同向，禁止无 Pass A 支撑写「讲解清晰」）

## 优先改进 Top 3

| 排序 | 类型 | 问题 | 证据摘句 | 改法 |
| ---- | ---- | ---- | -------- | ---- |

（类型权重：准确性 > 讲清度 ≥ 案例 > 结构/递进 > 表达/沟通。
若 Top3 全为结构/沟通，须有一句：「Pass A 未给出高置信知识/讲清度 issue；本表侧重结构/沟通。」）

## 教学能力摘要（授课力 · 本步展开 V1–V4）

- V1 专业力：（知识准确性、案例合理与适配；必须对齐 Pass A summary / findings，不得另起专业结论）
- V2 设计力：（各小闭环是否闭合；小闭环之间衔接是否自洽；lab 时对照 L1/L2/L3）

- V4 沟通力：（是否有提问 / 设问；提问须具体、不空泛；无证据写「转写未体现」）
- V5 / V6：本步不展开（非本版门禁）

（不打考核分）
```

## 授课媒介（本仓默认）

本仓适用的线下 / 线上培训场景以**共屏（桌面共享）**授课：教师桌面上的 PPT、笔记软件（如 Typora）、IDE 等推送到每位学员屏幕。**不使用黑板板书**。

- 改法与「待回放」请写「在共屏 PPT / 笔记 / IDE 中演示」，**禁止**默认写「板书」「粉笔」「黑板」。
- 若转写出现「写到本上」等，通常指学员笔记或共屏文档，不要推断为教师板书。

## 实操课（`lesson_type=lab`）

当用户给出 `lesson_type=lab` 时额外遵守（报告契约 §10 / ADR-0006）：

1. **禁止**用原理课口径「why→what→how→verify」夸奖本课递进。
2. **禁止**把「两种验证方式并列都教了」写成优点（主线上装完→启动→再验等**分步确认**除外）。
3. **禁止**把「主线未完就展开备选源 / 扩展工具」写成加分项；官网若是最短主线则算主线。
4. **推荐讲解路径**：**作用 → 实操 → 验证 → 总结注意事项 → 扩展**。若本课是「作用 → 注意事项前置 → 实操 → 验证」或安装中途展开官网，Top3 / 合格线须给出上述改法路径（有摘句），不要只夸「有注意事项」。
5. **Top3 选题**：准确性 / 讲清度（若有）之后，优先 **L1 ≥ L2 ≥ L3**，再普通小闭环或深度提问；少用「再多问几个为什么」挤掉实操闭环；口头禅默认水平线。
6. L3 的「默认验证」可以是命令、服务状态、能否开机/连上等，**不要**写成只认某一语言的 CLI。

## 约束

1. **Top 3 / 合格线中的知识准确性、讲清度与案例问题**，只能来自 Pass A 中 `verdict=issue` 且 `confidence=high` 且有摘句、且 `category` 为 `accuracy` / `clarity` / `case` 的条目；不得新造「必改」专业指控。
2. Top 3 选题权重：**准确性 > 讲清度 ≥ 案例 > 结构/递进 > 表达/沟通**；不足 3 条可不凑数。本段讲清度优先于「课表后半截未上」类结构项。lab 时结构类优先看 L1/L2/L3。
3. Pass A 的 `unverified` / `coverage_gap` / `low` **不要**写进合格线或 Top3 必改；可在水平线旁注「待核实」。
4. **表达噪声闸门**：口头禅、边打字边讲、截屏操作指令等，若摘句无法证明损害理解或合格线，默认只进水平线或不写，**不得**进 Top3 / 合格线。
5. 不要重复粘贴整份 Pass A JSON；专业细节由报告渲染器展示。不要把整份 `structure.md` 粘进教学能力段。
6. 对事不对人；完整句子；合格线与水平线分开；承认逐字稿边界，不确定则进「待回放确认」。
7. 遵守上文「授课媒介」：改法与待回放不假设黑板板书。
8. **禁止**展开 V5 / V6 正文；固定写「本步不展开（非本版门禁）」。
9. 前三节面向老师阅读，语气克制、可执行；后两节供维护者报告使用，可更细。
10. **直接输出 Markdown 正文**；禁止用 ``` / ```markdown 包裹整篇；禁止「好的，已收到…」类前言。
