# 课评报告结构与验收

- **版本**：v0.1
- **日期**：2026-07-23
- **状态**：目标模板（`prompts/` 与渲染逻辑按本文对齐）

---

## 1. 报告原则

1. **先结论摘要**，再证据与改法。
2. **事实 / 判断 / 建议**分开写，避免混成一句定论。
3. **合格线**（必须改）与 **水平线**（锦上添花）分栏或分节。
4. 语气遵守三不三要；**对事不对人**；禁止公开羞辱式表述。
5. 证据尽量引用**纠错后逐字稿摘句**（可带大致时间段），不编造未出现的内容。

---

## 2. 单视频报告结构（`report.md`）

```markdown
# 课评报告 · 单视频

## 元信息

- 输入文件：
- 运行 ID：
- 生成时间：

## 结论摘要

（3～6 句：结构是否闭合、最优先改的一点、整体是否达合格线）

## 课程结构与要点

### 总—分—总自检

- 开场总：
- 分述要点：（列表）
- 结尾总：
- 明显缺口：（具体说明缺在哪一段、缺什么功能，如「无回扣学习目标」）

## 课堂表现（对齐授课力维度，摘要级）

（可选标签：讲解清晰度、案例与演示、互动与反馈等；无证据则写「本段转写未体现」）

## 提升建议

### 合格线（必须改）

| 问题 | 证据摘句 | 改法 |
| ---- | -------- | ---- |

### 水平线（可选优化）

| 建议 | 证据摘句 | 改法 |
| ---- | -------- | ---- |

## 附录

- 纠错逐字稿：见 `transcript_corrected.md` 或内链
```

## 3. 模块模式附加结构

在单视频各段处理完成后，增加**模块层**（可合并为同一 `report.md` 顶部章节）：

```markdown
## 模块层结构（跨视频）

### 模块总—分—总

- 模块开场总：
- 各视频在模块中的角色：（01…05 各一句）
- 模块收束总：
- 嵌套缺口：（例如「02 缺少知识点内的小结」「模块末未回扣就业场景」）

## 各视频课评

### 视频 01 ·{文件名}

（单视频子结构精简版：结构要点 + 合格线/水平线建议）

### 视频 02 ·…

…
```

模块模式验收：**必须同时存在**模块层与各视频层；不能只有拼接的五份独立报告而无模块总述。

## 4. 验收检查表（维护者试用）

- [ ] 结论摘要是否可在 30 秒内读懂？
- [ ] 是否至少有一条建议指向**具体段落或时间点**？
- [ ] 合格线与水平线是否混淆？
- [ ] 术语纠错是否忠实原意（随机抽 3 处对照 raw / corrected）？
- [ ] 模块模式是否指出**跨视频**嵌套问题（若有）？
- [ ] 全文是否避免指名批评教师、校区负责人或学员？

---

## 5. 与上游标准的映射（提示词层）

报告中的维度标签与检查项，应可追溯到上游文档（路径见 [上游标准引用](../02-architecture/003_upstream-standards_上游标准引用.md)）。提示词中写清引用路径与版本，不在报告里宣称「组织硬性制度」除非上游已发布。
