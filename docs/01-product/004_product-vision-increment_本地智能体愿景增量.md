## 2. 用户与 8～12 周成功标准

| 用户       | 场景                                    | 8～12 周定位                                           |
| ---------- | --------------------------------------- | ------------------------------------------------------ |
| **维护者** | 全国授课视频：**批量筛** + **单段深评** | **唯一成功标准：我能稳定抽检**                         |
| 老师       | 单视频打磨 + 课程设计辅助               | 本机可跑；报告语气向完整授课力 / 课研可读靠拢（见 §4） |
| 学科       | 示范课课改、设计力补细                  | 用 16 天示范课边学边验；辅产物后置                     |

**成功标准操作定义（抽检）：** 对任意抽中的单段视频，能在本机跑通 `run`，经纠错稿闸门后得到可读的结构 / 主线 / 课型相关改法，并愿意据此做私下对齐；批量路径继续用 `batch-conduct` 做筛查与点选，不把 summary 当教练报告。

## 4. 检测项分层（对齐 15 项愿望清单）

### 4.1 Now（结构 / 主线 / 课型包加深）

优先服务「调课」与稳定抽检：

- 纠错稿 → 总分总 / 小闭环 / **主交付** / 反硬套总分总（E4c-2 已合入）
- 主线 vs 扩展、先主后扩、扩展是否适量（规则对齐上游课型专文）
- 概念准确性与示例贴合（Pass A，守假阳性闸门）
- 视频课型识别 → **原理 + 实操 + 代码** 三类先打透达标与改法
- 报告呈现：**结构 / 主线 / 交付** 优先于数字力画面细节

### 4.2 Next（仍属转写主链）

- 粘贴 / 跟敲可证线索（E4c-3）
- 金样例回归与带教 / 老师可读验收（E4c-5）
- 一天讲练结合 / 练习点（日课层，依赖目录线索 + A01）
- 阶段第一课、案例、项目课型包（在原理/实操/代码稳定后）

### 4.3 Later（声学与模型）

- 语速、起伏与情绪线索、提问后停顿等待（旁路；默认不进合格线，防误伤）
- 业务向小模型 / 微调（须先有金样例与修正记录评测集）

### 4.4 老师端报告语气（与现行契约的张力）

- **愿望**：老师端默认可读 **完整六维 / 课研表语气**（利于打磨与课改）。
- **现行**：`coach.md` 裁剪为 V1–V4 短稿；V5/V6 不展开；课研表**不作门禁**。
- **过渡策略**（未改契约前）：
  1. 抽检成功标准仍守假阳性与合格线/水平线分栏；
  2. 另增或加长「老师打磨稿」时，六维可作**呈现与建议框架**，分数与课研表**不自动变成否决门禁**；
  3. 改报告契约前须单独开 Issue，避免抽检误伤与课研打分混用。

## 5. 16 天示范课实验（方法）

- 材料：学科示范课（按上游备课方法模式录制；设计力 / 数字力仍有提升空间）；放本机 `data/`，不入库。
- **第一轮**：维护者自选不同课型，**先单视频**跑调课 Agent（结构 / 主线 / 课型 / 改法）。
- 目的双轨：自学构建知识体系 + 发现工具缺口写入修正记录 / backlog 发现池。
- 不做：第一轮整阶段强制全量批处理替代单段深评。
