## 1. 学习目标

读完本文后，应当能够：

1. 用自己的话区分：聊天模型、固定流水线、智能体；
2. 说明本机智能体如何读写本地文件（模型本身不「长硬盘」，工具在本机执行）；
3. 说清本仓 **`prompts/` 不是 Cursor Skills**，以及各自服务谁；
4. 知道「更灵活、能自主选择」应落在流水线路由，还是研发向 Skill，避免分心做 GUI / 对话壳。

---

## 2. 什么是智能体

智能体（Agent）不是某一款软件的品牌名，而是一种**工作方式**：

| 形态         | 行为                                                          | 例子                                       |
| ------------ | ------------------------------------------------------------- | ------------------------------------------ |
| 聊天模型     | 问一句答一句，默认不碰你的电脑                                | 网页里问「总分总怎么讲」                   |
| 带工具的助手 | 按你点的按钮调用固定能力                                      | 界面上点「转写」                           |
| **智能体**   | 你给**目标**，它在约束内反复：**想 → 用工具 → 看结果 → 再想** | 「把这段课评完，结构问题要写出可执行改法」 |

四个要素：

1. **目标**（例如：产出可读课评）
2. **工具**（读文件、跑 CLI、调 API、写报告）
3. **循环**（根据上一步结果决定下一步）
4. **边界**（不能删库、课例不进 Git、危险操作要人确认等）

本仓愿景里的「本地智能体」：目标在本机完成课评；工具是本机 CLI 与文件；**一年内不做账号门户**。

## 3. 工作形态（从简单到复杂）

```text
你：目标 + 约束
        │
        ▼
   ┌─────────────┐
   │  规划 / 推理 │  ← 大模型
   └──────┬──────┘
          │ 选一个工具
          ▼
   ┌─────────────┐
   │ 工具执行     │  ← ffmpeg / Whisper / lesson-review / 读写 md
   └──────┬──────┘
          │ 结果回填
          ▼
   够了？──否──► 再规划
     │是
     ▼
   交付物（报告、摘要）
```

| 阶段          | 形态           | 和本仓的关系                                          |
| ------------- | -------------- | ----------------------------------------------------- |
| **A（当前）** | 固定流水线 CLI | `lesson-review run`：步骤写死，最稳，服务「稳定抽检」 |
| **B**         | 脚本薄封装     | 选文件 → run → 打开报告；老师少记命令                 |
| **C**         | 对话式 Agent   | 「评这个 principle 视频」→ 模型选工具、可多轮         |
| **D**         | IDE 型 Agent   | 类似 Cursor：聊天 + 改工程 + Skills；偏研发           |

阶段看板约定：**先把 A 做硬**；B/C/D 后置，避免评课主链分心。

## 4. 能否操作本地文件？如何操作？

**能。** 条件是：进程跑在你电脑上，并且通过**工具代码**读写磁盘——不是模型「直接长出」文件权限。

| 方式                        | 本地文件                                           |
| --------------------------- | -------------------------------------------------- |
| 纯网页聊天                  | 通常不能直接改你磁盘                               |
| 本机 CLI（`lesson-review`） | **能**（读写 `data/`、`output/`）                  |
| Cursor / 本机 Agent         | **能**（读文件 / 写文件 / 跑终端；范围可沙箱限制） |

对话式 Agent 时，多一步「模型发起工具调用」，例如：

1. 调用 `lesson-review run …`
2. 再 `read` `output/.../structure.md`
3. 根据内容决定是否只重跑教练或提示你过纠错稿闸门

安全习惯（与本仓硬约束一致）：尽量限制在项目目录；课例与 API Key 不进 Git；破坏性操作需人确认。

## 5. 本仓 `prompts/` 算 Skills 吗？

**不算 Cursor 意义上的 Skills。** 两者都是「说明书」，但**谁加载、何时用、服务谁**不同。

|          | 本仓 `prompts/*.md`                                | Cursor **Skills**（`SKILL.md`）                     |
| -------- | -------------------------------------------------- | --------------------------------------------------- |
| 是什么   | 课评流水线某一步的系统提示词                       | 给「聊天里 Agent」的专项任务说明书                  |
| 谁加载   | Python **写死**（如结构步必载 `structure_single`） | Agent **按 description 判断**是否读取；或你手动启用 |
| 消费者   | `lesson-review run` / `batch-conduct`              | Cursor 里协助你改产品、写文档的 Agent               |
| 目标     | 输出格式稳、口径对齐契约                           | 对话任务可复用、少重复口述                          |
| 本仓现状 | 有完整一套（`src/lesson_review/prompts.py` 引用）  | 可选；与 CLI 无自动打通                             |

流水线里常见组合（示意）：

```text
纠错   → system_tone + asr_correct
Pass A → system_tone + knowledge_cases
结构   → system_tone + structure_single
提纲   → system_tone + teaching_outline
教练   → system_tone + coach_feedback
```

结论：

- 改 `prompts/coach_feedback.md` → 影响**每次自动课评**。
- 写 Skill「如何写修正记录」→ 影响**你在 Cursor 里协作改工具**的方式，**不会**自动进入老师跑的 `run`。

另：**Rules**（如 `.cursor/rules/lesson-review-ai.mdc`）偏常开「宪法」；Skills 偏按需「兵法」；`prompts/` 偏产线「工位作业指导书」。

## 6. Cursor Skills 怎么用（简要）

### 6.1 目录形态

```text
.cursor/skills/some-skill-name/
  SKILL.md           # 必填
  reference.md       # 可选
  scripts/           # 可选
```

`SKILL.md` 需含 YAML frontmatter，**`description` 要写清触发场景**（Agent 靠它决定要不要加载）。

### 6.2 存放位置

| 位置                     | 范围                       |
| ------------------------ | -------------------------- |
| 项目 `.cursor/skills/`   | 本仓库协作共享（可进 Git） |
| 个人 `~/.cursor/skills/` | 仅自己、跨项目             |

不要把自定义 Skill 放进 Cursor 内置目录 `~/.cursor/skills-cursor/`（系统保留）。

### 6.3 使用方式

1. **自动**：你的话匹配 description → Agent 读取该 Skill 再执行。
2. **手动**：在对话中选用 / 附上某个 Skill（视客户端 UI）。
3. **不会**：仅因为写了 Skill，`lesson-review run` 就自动换提示词——除非产品代码显式去读。

## 7.「更灵活、能自主选择」应落在哪一层

避免把三件事缠成一句话：

| 层             | 含义                                           | 改哪里                                              |
| -------------- | ---------------------------------------------- | --------------------------------------------------- |
| ① 流水线内路由 | 课型=principle → 原理检查包；粘贴多 → 加重条款 | **CLI + `prompts/` + 契约**（评课主链）             |
| ② 研发协作     | 修正记录怎么写、改 prompts 前对哪节契约        | **Cursor Skills / Rules**                           |
| ③ 老师对话壳   | 「重点看主交付」→ 调 run / 读报告              | **Later**：GUI 或对话 Agent，底层仍调同一套 prompts |

当前阶段（稳定抽检）：优先 ①；② 可按需补 1～2 个研发 Skill；③ 不抢主链。

## 8. 和图形化产品的关系（一笔带过）

若将来 CLI → 本机图形化（聊天 + 出结果 + 挂 Skills）：

- **引擎**仍应是现有流水线与 `prompts/`；
- **壳**负责选文件、展示报告、可选对话；
- **Skills** 可做成「技能卡片」映射课型包，或继续给研发用 Cursor Skills。

详细方案选型不在本文展开；未开始前以评课主链为准。

1. 老师本机只跑 `uv run lesson-review run …`，会不会加载你写在 `.cursor/skills/` 里的 Skill？为什么？
2. 要把「原理课合格线收窄到 1～2 个机制交付」变成**每次自动课评**的行为，应改 Skill 还是 `prompts/`？
