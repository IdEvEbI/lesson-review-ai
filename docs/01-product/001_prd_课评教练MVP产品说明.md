## 1. 问题陈述

听课与带教复盘依赖个人经验，难复制；样片多时，难以对每一段视频给出稳定、可执行的反馈。课评教练把「听懂讲了什么 → 对照总分总与教学标准 → 给出改法」做成可重复流水线，先服务维护者本人迭代口径，再逐步交给导师带新人。

## 2. 维护者与目标

| 项   | 说明                                                                                   |
| ---- | -------------------------------------------------------------------------------------- |
| 用户 | 本仓维护者，职责为教学质量相关赋能与工具先行                                           |
| 角色 | 质量架构师 / 发现者 / AI 先行者                                                        |
| 场景 | 线下现场培训与线上培训（具体品牌不在本仓公开文档中展开）                               |
| 媒介 | **共屏（桌面共享）**：教师 PPT、笔记软件、IDE 等推送到每位学员屏幕；**不使用黑板板书** |
| 课型 | 预留 `principle` / `code` / `lab`；实操课评价套路见报告契约 §10（文档先行）            |
| 推动 | 教学质量相关事实向上对齐决策层；校区改进通过校区负责人推动                             |

详细定位、飞轮、授权与「三不三要」见上游：`docs/00-定位与方法/001_role-charter_质量架构师角色宪章.md`。

**工程目标**：做出可演示、可迭代的课评教练流水线，把课堂视频变成结构清晰、建议可执行的报告。

**业务目标（对齐宪章成功画像）**：

- 半年视角：校区感到来的人是给方法的，工具是教练不是监工。
- 一年视角：具备可用的 AI 辅助质量监控 / 带教复盘能力。
- 本 MVP：先让维护者自己用得起来；再交给分校导师带新人复盘；成熟后才考虑老师自查。

### 2.1 目标用户与场景（MVP）

| 用户         | 场景                         | MVP 是否覆盖   |
| ------------ | ---------------------------- | -------------- |
| 维护者本人   | 单节课复盘、巡课后自测提示词 | 是             |
| 分校导师     | 带新人看视频复盘             | 否（内测阶段） |
| 全体老师自查 | 自愿上传自查                 | 否             |

**MVP 第一用户只有维护者本人**；报告默认私密，不进入公开考核或羞辱性场合。

### 2.2 处事风格（报告与产品文案必须遵守）

1. **建系统，不挑刺**：输出可执行改法，避免只堆批评。
2. **三不三要**：不公开批评校区负责人/教师；不越级指挥一线；不只带问题走；要私下对齐；通过校区负责人推动；带方法走。
3. **对事不对人**：报告默认私密；分享给新人时由导师控制场合。
4. **合格线 vs 水平线**：必须改的与锦上添花的要分开写；不要把发展项写成进班否决语气。
5. **先可读，再短**：完整句子；禁止电报体；中英文之间保留空格。
6. **公开仓脱敏**：不写维护者真名、所在机构或对外品牌名。

## 3. 产品能力（In Scope）

### 3.1 输入模式

| 模式       | 输入                         | 排序规则                       |
| ---------- | ---------------------------- | ------------------------------ |
| 单视频     | 1 个视频或音频文件           | 不适用                         |
| 模块批处理 | 手动选定的 3～5 个同模块视频 | 文件名前缀数字升序（如 `01_`） |

- 不自动判断「是否同一模块」；缺号、重号应**警告**，仍按数字排序。
- 假设：单视频为总分总；模块内为总分总嵌套。

### 3.2 流水线（用户可见步骤）

1. **抽轨**（仅视频）：得到用于转写的音频。
2. **转写**：生成带时间信息的原始逐字稿。
3. **纠错**：在保留术语的前提下减少口误与 ASR 噪声；避免「改顺了却改错专业含义」。
4. **结构与要点**：单视频一层；模块模式输出**模块层 + 各视频层**。
5. **提升建议与改法**：区分合格线与水平线；对事不对人；少套话。

### 3.3 输出

- 默认：**一份 Markdown 课评报告**（路径见 [003 报告契约](./003_report-contract_报告结构与验收.md)）。
- 可选中间产物（本地 `output/`，不入库）：原始转写、纠错稿、运行清单（manifest）。

### 3.4 交互形态（MVP）

- **CLI**：维护者在终端指定输入与模式，等待流水线完成，在 `output/` 阅读报告。
- **不做**：Web 门户、账号体系、多人协作、自动归模块。

### 3.5 旁路能力（非课评主路径）

- **`batch-conduct`**：对目录内多个视频按文件名前缀数字排序，执行抽轨 → 转写 → 纠错 → **言行扫描**（脏话、贬低前任/其他讲师等，须摘句）。
- 用途：投诉核查、课堂用语证据汇总；**不**跑结构 / Pass A / 教练报告。
- 输出：`output/conduct_*/summary.md` 与各段 `transcript_corrected.md`、`conduct_scan.json`。操作见 [004 言行扫描](../90-guides/004_batch-conduct_言行扫描速查.md)；契约见 [CLI 契约](./002_cli-contract_CLI命令与运行契约.md)。

## 4. 成功标准（可验收）

满足以下全部条件时，视为 MVP 竖切过关：

1. 在维护者提供的**脱敏样例**上，单视频模式端到端跑通并产出报告。
2. 在至少一组 **3～5 个**模块视频上跑通，报告含模块层与各视频层结构。
3. 报告能指出总分总或嵌套上的**具体缺口**（非泛泛而谈）。
4. 建议能落到「哪一段 / 缺什么 / 怎么改」，并区分合格线与水平线。
5. 维护者愿意把该工具纳入个人复盘习惯（主观但关键）。

---

## 5. 明确不做（Out of Scope）

- 全员自查产品化、复杂权限、绩效默认挂钩
- 自动模块归类
- AI 语音 + PPT 生成正式授课成片
- 讲义 / 教案 / 大纲一键完美生成（愿景阶段 ②）
- 在本仓另立「组织级教学质量总标准」
- 未授权情况下把真实课评报告写入公开月报或公开批评场合
- 把工具默认做成全员绩效考核入口

## 6. 非功能需求（MVP 级）

| 维度   | 要求                                                                          |
| ------ | ----------------------------------------------------------------------------- |
| 隐私   | 真实课例媒体与 API 密钥不进 Git；转写默认本地 ASR                             |
| 可复现 | 每次运行记录模型、提示词版本、输入指纹（见架构 manifest）                     |
| 可替换 | LLM 提供商可通过配置切换（默认 DeepSeek）                                     |
| 可维护 | 提示词与代码分目录版本化；改评价维度先对上游再改 `prompts/`                   |
| 性能   | 在 M 系列 Mac（24GB）上，单节 45～90 分钟课例可在合理时间内完成（不作硬 SLA） |

## 8. 测试与验证策略（MVP）

- **无自动化 CI 门禁为硬性要求**（种子阶段）；里程碑 PR 合并前维护者试用报告质量。
- **回归课例**：固定 1 个单视频 + 1 组模块视频；改 `prompts/` 后对比报告差异。
- **人工检查清单**：语气（三不三要）、合格线/水平线、术语是否被误改、结构是否双层（模块模式）。
