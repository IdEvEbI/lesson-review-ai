- **版本**：v0.2
- **日期**：2026-07-25
- **状态**：已确认（维护者 2026-07-25；实现按本文与 ADR-0004）
- **关联 ADR**：`docs/02-architecture/adr/0004_two-pass-knowledge-review.md`

## 1. 报告原则

1. **先结论摘要**，再证据与改法。
2. **事实 / 判断 / 建议**分开写，避免混成一句定论。
3. **合格线**（必须改）与 **水平线**（锦上添花）分栏或分节；另设 **待核实**（默认不进 Top3 必改）。
4. 语气遵守三不三要；**对事不对人**；禁止公开羞辱式表述。
5. 证据尽量引用**纠错后逐字稿摘句**（可带大致时间段），不编造未出现的内容。
6. **假阳性优先于召回**：无摘句不得判「必须改」的知识/案例错误；标题锚点不是讲义全文。
7. **优先改进 Top 3** 选题权重：**知识准确性 > 案例恰当性 > 结构与递进 > 表达与沟通**。

## 2. 流水线与产物（单视频）

| 顺序 | 步骤                         | 主要产物                  |
| ---- | ---------------------------- | ------------------------- |
| 1    | 抽轨 / 转写 / 纠错           | `transcript_corrected.md` |
| 2    | **Pass A 专业预审**          | `knowledge_review.json`   |
| 3    | 结构（总分总、小闭环与递进） | `structure.md`            |
| 4    | Pass B 综合建议与成稿        | `coach.md`、`report.md`   |

Pass B **必须消费** Pass A JSON；不得无视闸门另起专业指控。

## 3. `knowledge_review.json`（Pass A 契约）

### 3.1 顶层字段

| 字段              | 说明                                                  |
| ----------------- | ----------------------------------------------------- |
| `schema_version`  | 如 `1`                                                |
| `title_anchor`    | 所用标题锚点（通常来自文件名 stem）                   |
| `anchor_strength` | `strong` \| `weak`（标题过泛时为 weak，结论须更保守） |
| `summary`         | 2～4 句专业预审摘要（对事不对人）                     |
| `findings`        | 数组，见下表                                          |

### 3.2 `findings[]` 元素

| 字段          | 说明                                                           |
| ------------- | -------------------------------------------------------------- |
| `id`          | 稳定短 id（如 `k1`）                                           |
| `category`    | `accuracy` \| `case` \| `coverage_gap`                         |
| `claim`       | 一句话判断（事实与评价分开语气）                               |
| `evidence`    | 纠错稿摘句；可含 `approx_time`；**无摘句则不得为 issue**       |
| `verdict`     | `pass` \| `issue` \| `unverified`                              |
| `confidence`  | `high` \| `low`                                                |
| `remediation` | 可选改法（issue 建议有；unverified 可写「对照讲义/回放确认」） |

### 3.3 闸门（实现必守）

| 规则                           | 行为                                                      |
| ------------------------------ | --------------------------------------------------------- |
| 无 `evidence` 摘句             | 禁止 `verdict=issue`                                      |
| `coverage_gap`（标题暗示漏讲） | 默认 `unverified`，不进合格线 / Top3                      |
| 进入合格线 / Top3              | 仅 `verdict=issue` **且** `confidence=high` **且** 有摘句 |
| `unverified` / `low`           | 只进报告「待核实」或水平线旁注                            |
| Pass B                         | 不得新增无 Pass A 支撑的 knowledge `issue`                |

## 4. 单视频报告结构（`report.md`）

```markdown
# 课评报告 · 单视频

## 元信息

- 输入文件：
- 标题锚点：
- 运行 ID：
- 生成时间：
- 说明：专业判断仅基于转写与标题锚点，不是对照完整讲义的判分。

## 结论摘要

（3～6 句：专业预审要点、结构是否闭合、Top1 优先改进）

## 优先改进 Top 3

| 排序 | 类型 | 问题 | 证据摘句 | 改法 |
| ---- | ---- | ---- | -------- | ---- |

（类型权重用于选题：准确性 > 案例 > 结构/递进 > 表达/沟通；不足 3 条可不凑数。）

## 专业预审（知识与案例）

### 知识准确性

（汇总 Pass A 中 category=accuracy 的 findings）

### 案例恰当性

（汇总 Pass A 中 category=case 的 findings）

### 待核实

（unverified / coverage_gap / low confidence；默认不要求当次必须改）

## 课程结构与要点

### 总—分—总自检

- 开场总：
- 分述要点：
- 结尾总：
- 明显缺口：

### 小闭环与递进

- 各段小闭环是否清楚：
- 递进关系：
- 缺口：

## 教学能力摘要（授课力六维 · 有证据才写）

（V1–V6 摘要；无证据写「转写未体现」；不打考核分、不做否决语气。）

## 提升建议

### 合格线（必须改）

| 问题 | 证据摘句 | 改法 |
| ---- | -------- | ---- |

### 水平线（可选优化）

| 建议 | 证据摘句 | 改法 |
| ---- | -------- | ---- |

## 附录

- 纠错逐字稿：`transcript_corrected.md`
- 专业预审：`knowledge_review.json`
```

## 5. 模块模式附加结构

在单视频各段处理完成后，增加**模块层**（可合并为同一 `report.md` 顶部章节）：

```markdown
## 模块层结构（跨视频）

### 模块总—分—总

- 模块开场总：
- 各视频在模块中的角色：（01…05 各一句）
- 模块收束总：
- 嵌套缺口：

## 各视频课评

### 视频 01 ·{文件名}

（单视频子结构精简版：专业预审摘要 + 结构要点 + Top 项）
```

模块模式验收：**必须同时存在**模块层与各视频层。模块级专业预审可在 E5 再定；本版先保证单视频 Pass A/B。

## 6. 验收检查表（维护者试用）

- [ ] 结论摘要是否可在 30 秒内读懂？
- [ ] Top 3 是否遵守权重，且无「无摘句却必改」的知识/案例项？
- [ ] 「待核实」是否与合格线分开？
- [ ] 合格线与水平线是否混淆？
- [ ] 术语纠错是否忠实原意（随机抽 3 处对照 raw / corrected）？
- [ ] 全文是否避免指名批评教师、校区负责人或学员？
- [ ] 是否误把标题当完整讲义标准而扩大指控？

| 报告块           | 上游主要参照                                                          |

| 知识 / 案例预审  | `002_教学能力模型_授课力维度体系_双场景.md` · V1 专业力（可观察部分） |
| 结构与小闭环递进 | 同上 · V2 设计力（及与 V5 闭环相关的可观察部分）                      |
| 表达 / 沟通      | 同上 · V3 / V4（Top3 权重靠后）                                       |
| 语气与合格线     | 角色宪章三不三要；本仓 PRD §2.2                                       |
